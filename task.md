# ЗАДАЧА

Создай проект "arena-bridge": локальный OpenAI-совместимый API-сервер, который пересылает запросы в веб-интерфейс arena.ai (бывший LMArena), получает ответ модели и возвращает его клиенту в формате OpenAI. Каждый запрос выполняется в НОВОМ чате на arena.ai, после получения ответа этот чат УДАЛЯЕТСЯ, чтобы не засорять аккаунт.

Проект будет использоваться ТОЛЬКО в личных целях, на моём аккаунте, и должен работать на телефоне Android в Termux (без root). Разрабатывать можно на ПК, но итог обязан запускаться в Termux.

# КАК Я ЭТО ИСПОЛЬЗУЮ

Я захожу в любое приложение/сайт, которое умеет подключаться к OpenAI-совместимому API (чат-клиенты, боты и т.д.), и ввожу:
- Base URL: http://127.0.0.1:PORT/v1
- API Key: свой ключ, заданный в конфиге
- Model: название модели с arena.ai (например, как оно называется в списке моделей на сайте)

Отправляю сообщение, сервер создаёт чат на arena.ai с выбранной моделью, ждёт ответ, отдаёт его мне, удаляет чат.

# РЕКОМЕНДУЕМАЯ АРХИТЕКТУРА (основная)

Headless-браузеры (Playwright/Puppeteer) в Termux работают нестабильно, а Cloudflare и reCAPTCHA на arena.ai блокируют обычные HTTP-клиенты. Поэтому основная схема такая:

1. Сервер на Python (FastAPI или aiohttp + uvicorn) в Termux. Он поднимает:
   - OpenAI-совместимый HTTP API;
   - WebSocket-эндпоинт для "моста" (только localhost).
2. Userscript (для Tampermonkey/Violentmonkey в Firefox для Android или Kiwi Browser), который висит на открытой, залогиненной вкладке arena.ai. Он подключается по WebSocket к серверу и выполняет задания: в контексте настоящей страницы (с реальными куками, токенами и капча-токенами) отправляет сообщение, читает ответ и удаляет чат.
3. Сервер получает запрос от клиента, ставит его в очередь, отправляет задание userscript'у, получает куски ответа (стриминг), пересылает их клиенту.

Так как все действия выполняются изнутри реальной вкладки, проблемы Cloudflare и капчи сводятся к минимуму.

Если по результатам исследования окажется, что эта схема неработоспособна, предложи и реализуй запасной вариант (например, прямые HTTP-запросы с куками и curl_cffi, или браузер в proot-distro) и ОБЪЯСНИ причину переключения.

# ТРЕБОВАНИЯ К API СЕРВЕРА

- GET /v1/models: список моделей (берётся из arena.ai и кэшируется; плюс возможность задать список вручную в конфиге).
- POST /v1/chat/completions:
  - поддержка stream: true (SSE, формат data: {...} и финальный data: [DONE], как у OpenAI) и stream: false;
  - поле model определяет модель на arena.ai; если модель неизвестна, верни ошибку 404 в формате OpenAI;
  - messages (system/user/assistant) склеивай в один промпт с понятной разметкой ролей, так как веб-интерфейс принимает одно сообщение. Системный промпт добавляй в начало. Формат склейки вынеси в настройки;
  - параметры temperature, max_tokens, tools и т.д. принимай, но игнорируй без ошибки (залогируй, что проигнорированы);
  - если в messages есть изображения (content-массив с image_url), в первой версии верни понятную ошибку или проигнорируй с предупреждением.
- Авторизация: заголовок Authorization: Bearer <ключ>. Ключ берётся из конфига/переменной окружения. Без ключа или с неверным ключом возвращай 401. Если ключ не задан, сгенерируй случайный при первом запуске и выведи в консоль.
- Формат ошибок: как у OpenAI ({"error": {"message", "type", "code"}}).
- CORS включён (чтобы работали веб-клиенты).
- По умолчанию слушай ТОЛЬКО 127.0.0.1. Возможность открыть на 0.0.0.0 только по явному флагу, с предупреждением о безопасности.

# ЛОГИКА ЧАТОВ

- Один запрос клиента = один новый чат на arena.ai.
- После завершения ответа (успешно, с ошибкой или при обрыве соединения клиентом) чат ДОЛЖЕН быть удалён. Используй try/finally. Если удаление не удалось, добавь ID чата в файл очереди на повторное удаление и повтори при следующем запуске/по таймеру.
- Очередь: по умолчанию обрабатывай запросы последовательно (1 одновременно); параметр MAX_CONCURRENCY в конфиге. Лишние запросы ждут в очереди с таймаутом.
- Таймауты: на ожидание начала ответа и на общее время (настраиваются).
- Если userscript не подключён, возвращай 503 с понятным текстом "Откройте вкладку arena.ai с включённым userscript".
- Сделай heartbeat (ping/pong) на WebSocket и автопереподключение в userscript.
- Защита от случайной потери данных: удаляй только чаты, созданные самим мостом (запоминай их ID), и никогда не трогай чужие.

# ТРЕБОВАНИЯ К TERMUX

- Только то, что реально ставится в Termux без root: Python 3 из pkg, pip-пакеты без тяжёлой нативной компиляции. Избегай зависимостей, требующих Rust/C-сборки, если есть чистые Python-альтернативы (например, предпочти aiohttp/starlette/uvicorn без extras; если нужен pydantic v2, проверь, что ставится).
- Напиши install_termux.sh: pkg update, установка python и нужных пакетов, создание venv, pip install -r requirements.txt, создание конфига из примера.
- Напиши run.sh, который запускает сервер и вызывает termux-wake-lock, чтобы Android не убивал процесс. Подскажи в README про отключение оптимизации батареи для Termux.
- Минимальное потребление ресурсов.
- В README опиши установку Firefox для Android + Tampermonkey/Violentmonkey (или Kiwi Browser), как поставить userscript (сервер должен отдавать его по http://127.0.0.1:PORT/userscript.user.js, чтобы его можно было установить в один клик), как держать вкладку arena.ai открытой в фоне и как проверить подключение.
